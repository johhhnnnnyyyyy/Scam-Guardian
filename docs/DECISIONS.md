# Decisions and open proposals

## Implementation decisions made under build authorization
- Web companion + Node backend, as permitted by the brief. Preserve all capture-mode descriptions; same-phone remains experimental.
- Start with deterministic detection and an optional LLM adapter. Without LLM credentials show rules-only status.
- Standard warnings now prefer Timbre SSE with REST fallback; synthetic provider requests passed, browser/device playback is unverified.
- Family sharing now includes an opt-in Web Push adapter alongside foreground polling; real OS delivery is unverified.
- Retain transcripts in server memory until clear/delete/TTL/process restart; Stop ends capture but preserves the evidence. Browser-rendered transcripts remain until cleared or the page is closed. Explicit evidence downloads persist on the user's device.

These are implementation choices within the owner's existing brief, not approval of the product-direction proposals below.

## Owner decisions pending (do not silently implement as product changes)
1. Replace the label Safe with No warning detected. Rationale: safer uncertainty communication. Current build preserves Safe with a permanent qualification.
2. Promote companion-device capture above same-phone capture in product positioning. Current build simply discloses the verified platform constraint.
3. Choose practice drill over voice cloning for the challenge stretch goal. The current code includes local adapters for both, while this prioritization proposal remains pending.
4. Choose the primary two demo languages after native review and actual acoustic results.

## Stress test of the idea
Strong mechanism: interruption at the moment pressure is applied, supported by exact evidence. Weakest link: capture and transcription, not classifier sophistication. Quoted scam education, negation, both speakers in one transcript, sarcasm, adversarial instructions, silence and delayed provider segments all undermine naive keyword scoring. Language support is not detection-quality evidence. A family alert is useful only if consented, delivered, and noticed; a push adapter is useful only after actual background delivery is verified.

The supplied loss statistic is excluded from demo claims until an authoritative matching date/category source is verified. No interpretation of Indian recording law is settled by these documents. Legal/privacy review remains a real-user gate, not a claim of compliance.

## Implementation update — 9 November 2026 (roadmap batch 2: streaming resilience, language registry, hardening)

Authorized by the owner ("proceed to the next section"). Design and sources: the batch 2 design report. Values below are judgement unless marked; each numbered item is a **pending owner decision** that is easy to change in config.

11. Rate limits and the daily provider-call cap (`src/limits.js` `DEFAULT_LIMITS`; 500 paid provider calls per process per day, in memory, resets on restart). A full limiter table fails closed. `TRUST_PROXY_HOPS` defaults to 0, so proxy headers are ignored unless configured.
12. Session expiry slides: 5 minutes idle (audio frames and session actions count, GET polling does not) with a 60-minute absolute cap (`sessionIdleMs`, `sessionCapMs`). An open microphone on a quiet line keeps monitoring up to the cap. Family invites live as long as the session.
13. Live reconnect: up to 5 attempts with full-jitter backoff, a 5-second audio buffer replayed at up to 2× real time, audio already sent to a dropped connection is not re-sent, lost audio is recorded as `gaps` and disclosed. Lossless recovery is not possible because Gnani documents no resume. A 2-second reconnect is not promised.
14. Upstream rotation before Gnani's 15-minute connection limit at 13 minutes (hard 14.5), sequential with a `commit`, never overlapping (Gnani's concurrency cap is unpublished).
15. While the spoken warning plays, the browser pauses the microphone; the server sends silence upstream for up to 20 seconds to keep the audio clock aligned and shows "paused". Upstream billing for that silence is unknown.
16. Setup links now require a 6-digit code shown on the senior's device and approved from the signed-in family account that created the link; five wrong codes burn the link; a new device credential (stored only as a SHA-256 hash) is issued once and is revocable per device; device credentials expire after 30 idle days or 90 days. The senior's internal profile id is never sent to any client.
17. Evaluation: results are k/n with Wilson 95% intervals; a slice is "claimable" only with at least 30 scams and 30 benign items; held-out share 30% by group hash. No independent held-out set exists yet; it must be written after rules are frozen by someone who did not tune them, and native-reviewed. The new twins are development hard negatives.
18. Language registry: English, Hindi, Tamil `supported`; Bengali, Telugu, Kannada, Malayalam, Marathi, Gujarati, Punjabi `planned` (Gnani transcribes them, the detector has no rules, sessions show partly/not covered); Odia `not_offered`. Word lists need native review. Dakshina-derived data is not shipped pending a licence decision (CC BY-SA).

Unverified vendor facts that need an owner-permitted live test: whether `x-idle-timeout-sec: 900` keeps a silent stream open; whether `processing` and `transcript` pair first-in-first-out; whether `segment_id` prefixes change per connection; tolerance for 2× catch-up replay.

## Implementation update — 9 November 2026 (roadmap batch 3: language packs, dialogue acts, scam families, pre-rendered warnings)

Authorized by the owner ("proceed to the next section"). Research: the batch 3 design report. Each numbered item is a **pending owner decision**.

19. Detection rules now live in data-only language packs (`src/packs/en.js`, `hi.js`, `ta.js`) and run as a union over every clause, so code-mixed speech matches whichever pack each word belongs to. Adding a language means adding a pack plus warning copy and a voice. Some literals remain in `engine.js` (amount grammar, own-payment exception, remote-tool and TRAI checks); per-language warning and drill copy still live in `providers.js`/`server.js`.
20. Dialogue acts (B-5): each clause is `advice`, `reported`, `demand`, `narration`, `question` or `other`. Reported and narrated tactics are kept as **weak** evidence: shown in the ledger, excluded from family reasons, unable to escalate alone; two different weak tactics give "Be careful". A quoted request aimed at the listener ("the bank said share the OTP") stays **strong** — a senior recounting a real call may therefore see "Hang up"; the copy should name the reported frame (UI work pending). Unclassified (`other`) clauses stay strong, as before. A weak pretext (family emergency, authority, threat, prize, investment bait, secrecy, urgency, camera) becomes decisive once the same window holds a strong ask (payment, secret code, app/remote, identity, advance fee).
21. An English authority needs a claim ("this is", "I am from", "connecting you to", "… officer/department/calling"); a bare institution name ("customs duty", "CBI and police do not arrest…") no longer counts.
22. New tactics and danger combinations for eleven scam families (B-1, `DANGER_RULES` in `engine.js`), including source-backed contradictions: TRAI does not call about disconnection (TRAI PR 22/2025); a UPI PIN or QR scan is never needed to receive money (NPCI); "safe/verification account" and bail by phone. Also judgement additions beyond the notes: advance fees, shaming/extortion threats, remote + threat, family emergency + secrecy, investment bait + deposit. Tier-B "never" claims (bank OTP, KBC fee, electricity) are used only as advice cues. The I4C "no video-call arrest" rule rests on a news report.
23. Pre-rendered warnings (B-12): standard-voice warning audio is cached per language and risk on first use (`X-Warning-Source: cache|provider`), served without a paid call, and used as a fallback when the speech service fails — including, disclosed via `X-Warning-Fallback: standard-voice-cache`, when a cloned-voice warning fails. Cloned-voice audio is never cached. `PREWARM_WARNINGS=1` renders the six clips at startup (counted against the daily cap; off by default). The cache key does not yet include a copy/voice version; Gnani's terms on reusing generated speech have not been read (owner).

Measured on development data (the rules were tuned on it): scam-family set 59/59 at the expected level and 0/24 look-alikes alarmed; before tuning it was 15/59 and 5/24. Not done: ordered "ask after pretext" scoring and an UNCERTAIN tier (B-4/B-8), separate CLAIM/THREAT acts, per-pack native sign-off fields, an independent held-out set.

## Owner decisions recorded 2026-11-09
The owner chose the following for pending items 1–23, plus new items 24–25. Each item below is a decision; the code changes for them land in later batches.
- 1 Rename "Safe" to "No warning detected". 2 Lead with companion-device capture (a second device on speakerphone hears both voices); same-phone stays secondary. 3 The stretch goal is the practice drill. 4 Pick the demo languages after acoustic results.
- 5 A bare Aadhaar/PAN request is Be careful. 6 Hide the family timeline after the senior revokes sharing. 7 Keep the 1-senior / 5-account limits. 8 **Add file/SQLite persistence now** for accounts and profiles.
- 9, 10, 12–17, 20 and 23 stay as built (prewarm stays off until Gnani's terms are read).
- 11 Make the limits env-configurable (default cap 500/day). 18 Promote Bengali and Telugu to the next packs. 19 Move the remaining literals into packs.
- 21 A bare institution name counts as **weak** authority evidence. 22 Contradictions and family rules become weighted scores, with an uncertain tier.
- 24 Caller-vs-senior attribution. **Senior voice enrollment is compulsory** at setup. Attribution uses physical audio evidence: an enrolled-voice match plus a telephone-channel signature (the caller's voice arrives band-limited through the phone speaker; the senior's voice is direct, full-band). Text cues and turn-taking support that evidence. Attribution must be decided within about 1–2 seconds of each turn.
- 25 **The LLM becomes compulsory.** At call start it gives a provisional caller/senior assignment from the transcript and keeps a rolling call summary. Acoustic evidence overrides it once that evidence is confident. The LLM still cannot raise Hang up on its own.
- No attribution method is 100% certain. Each turn's speaker carries a confidence, and low-confidence turns are labelled "unsure" rather than guessed.

## Batch 4 implementation notes (9 November 2026)
- Done: decisions 1 (label renamed; Hindi/Tamil wording needs native review), 8 (DATA_DIR snapshot), 11 (env limits), 21 (bare institution names are weak "mention" evidence that a strong ask never promotes), 24 and 25.
- 24, as built: compulsory enrollment for live listening; per-turn audio comes from a 30-second in-memory ring buffer aligned on the audio clock. **senior** = voice matches AND the channel is live (both 3.6–7.6 kHz and 7.1–7.8 kHz present at the senior's enrolled level) AND neither the words nor the LLM disagree. **caller** = phone channel + a different voice (high confidence), or one acoustic test + the words/LLM (medium). Voice match + phone channel is a suspected clone or replay: always **unsure**. Turns under 1.5 s of voiced speech carry no voice evidence. Measured on synthetic signals: under 200 ms per turn.
- 24, turn-taking (10 November 2026): the turn right after one that was certainly the senior (high confidence) counts as one more vote for **caller**. With the phone channel or a different voice it gives a medium-confidence caller label; on its own it changes nothing, words pointing at the senior block it, and it can never produce "You". The live screen now shows the conversation as a chat: caller on the left, the senior on the right, unsure lines in grey with their honest label.
- Lure vs ask (10 November 2026, from manual role-play C24): a friendly announcement ("a bonus for pensioners") warned before the caller's real request arrived. Cause: the AI model's prompt never said that offers and announcements are not tactics, and any one grounded model flag raised the call to at least Be careful. Fix: the prompt now says to flag only the request or pressure itself and never a lone offer; and a model-only prize / guaranteed-returns / bare-authority flag is dropped until some other tactic (an ask) is present. The hand-written rules already kept such lines calm in all four languages. Not verified against the live model.
- Owner decisions, 10 November 2026 (asked in chat):
  - **Family link: link once, share every call.** Approved and built: `POST/DELETE /api/profile/family`, consent recorded as `family_sharing`, invite valid 24 h, withdrawal stops sharing at once. Per-call pairing still works.
  - **Interface: "warm and calm".** Approved and built: limestone paper, indigo-ink actions, leaf/turmeric/sindoor signal colours, Atkinson Hyperlegible body, Literata headings (self-hosted), a large signal lamp as the one strong element. Not yet seen by the owner or tested with older adults.
- Attribution, from owner testing (separate device, call on speaker; every line came out Caller): the senior facing the phone loses high frequencies smoothly, enough to pass the old 12 dB "phone" test, and one wrong certain-caller turn then taught the per-call caller print and the learned loudspeaker level. Fixed: "phone" now also needs a sharp cliff at a phone band edge (3.4 kHz or 7 kHz), 15 dB steeper than in the enrollment; the caller print counts only if it fits clearly better (3 points) than the senior's own print; the enrollment asks people to sit where they sit during calls. Thresholds uncalibrated; re-record the voice so the edge is measured. Not yet confirmed on the owner's setup.
- Malayalam / Manglish from speech recognition: English loanwords come back in Malayalam script (ബാങ്ക്, കെവൈസി) or mixed with Latin, while rules were written in one form or the other. Fixed with detection-only loanword renderings (src/loanwords.js; Malayalam only for now) and the short demand "പറഞ്ഞു താ". Spellings need native review (pending 29).
- **Pending 31 (owner):** transcription accuracy. Research (docs/STT_AUDIO_RESEARCH.md) found no evidence that cleaning the audio before Gnani helps; it usually hurts. Built: a live microphone check (clipping, near-silence, browser processing left on). Proposed next, each needing an A/B on recorded speakerphone clips: raise `x-max-speech-s` from 10 s (it cuts sentences, but longer segments delay warnings); benchmark Sarvam saaras:v4 / Google Chirp for Malayalam; enhancement only if a test shows a gain.
- **Pending 32 (owner):** loanword renderings for Hindi and Tamil (same problem likely, not yet measured).
- 24, limits stated honestly: the built-in voice print is a transparent spectral baseline (band shape within 300–3400 Hz plus pitch, normalised by the senior's own variation across the enrollment). It is not a neural speaker model and will confuse similar voices (for example a family member). A neural embedder (CAM++ / ECAPA-TDNN via sherpa-onnx or onnxruntime-node) plugs in through `voiceEmbedder`. **Every threshold is uncalibrated.** No accuracy figure can be claimed until an in-domain trial set exists: real speakerphone recordings across phone models, distances, narrowband/VoLTE calls, TV noise, overlap, and a cloned-voice split. Certifying ≤1% error on accepted turns needs about 300+ accepted turns with no errors (report: reports/Caller vs senior speaker attribution.md).
- 25, as built: the server refuses to start without an LLM unless `ALLOW_RULES_ONLY=1` (development only). The model returns per-segment roles and a ≤600-character rolling summary, which is kept only in the session and never shown to family or logged. Roles are recombined with the stored acoustic evidence and can only veto "senior" or confirm "caller".
- Not yet done: 18 (Bengali and Telugu packs), 19 (remaining literals), 22 (weighted scores and uncertain tier). These are planned for batch 5.
- Open: whether the companion device should also try an on-device neural embedder in the browser (onnxruntime-web), so the voice print never leaves the device.

## Owner decision and batch 5 notes (9 November 2026)
- **MVP language scope (owner, replaces the Bengali/Telugu choice in item 18):** English, Hindi, Tamil and Malayalam, including code-mixed Hinglish, Tanglish and Manglish. Other Gnani languages stay `planned` for later ("a few things that work great beat many that don't").
- Malayalam (`src/packs/ml.js`) is now `supported`. Script and Manglish patterns use stems (Malayalam suffixes attach after the stem). Chillu letters in the older ZWJ encoding normalise to atomic letters, and Malayalam digits normalise too. Sourced wording follows Kerala Police and bank advisories; everything else is composed and **needs native review**, as do the Malayalam UI and warning text. Timbre supports Malayalam, but no voice name is published, so warnings use the provider default voice; this is unverified until a credentialed call passes.
- 19 done: amounts, payment verbs, remote-tool names and "never calls" bodies now come from pack data.
- 22 done: `assess()` keeps the precise patterns and adds weighted evidence. Hang up = a pattern, or a score of at least 7 across at least 3 different strong tactics. "Be careful" is **uncertain** when the score is at least 4, which the senior and family see as "close to a known scam pattern". The TRAI contradiction and remote-tool names add weight. Weights are judgement calls (`WEIGHTS`, `SCORE` in engine.js).
- Per-user tuning (attribution): only high-confidence turns teach. The senior print re-centres slowly (α 0.05) and is capped near the enrollment; past the cap the profile is marked `needsReenroll`. Each device learns its phone-loudspeaker level from confident caller turns. A per-call caller print can only turn an unknown voice into "not the senior". Thresholds and the decision table never change, so a long-talking scammer cannot be learned as the senior (tested).
- English pack: "police station" alone is no longer an authority claim (found through a Manglish look-alike; English results unchanged).
